# OSS Evaluation: A4 Hatchet orchestration

- Status: Adopted for A4
- Date: 2026-09-05
- Related ADR: `docs/adr/0004-framework-responsibility-boundaries.md`

## Candidate

Hatchet TypeScript SDK 1.31.0 and Hatchet Embedded sidecar v0.105.16.

## Official repository

- https://github.com/hatchet-dev/hatchet
- https://github.com/hatchet-dev/hatchet-embedded

## License

MIT for the SDK and embedded sidecar repositories.

## Activity

The SDK registry release is 1.31.0. Embedded v0.105.16 was published on 2026-08-31. Both were checked on 2026-09-05.

## API / SDK

The official TypeScript v1 API supplies workflows, DAG tasks, retries, input-derived concurrency, worker slots and labels, durable event waits, and worker restart recovery. The embedded client supplies a local engine with bundled PostgreSQL and no Docker or cloud token.

## Self-host requirement

Yes for this Gate. The official embedded sidecar is downloaded into the SDK cache and run locally. Its bundled PostgreSQL data is user-local under Ubuntu-E. No cloud resource is created.

## Platform requirements

Canonical source and TypeScript compilation remain on Windows. The Linux amd64 sidecar runs under WSL Ubuntu-E with Node 20.20.2. The engine is pinned to v0.105.16 and the binary is verified against SHA-256 `68967396279f859c33897ed6228f2fa47874814a56de537fad4f4a31370921a6`.

## Overlap

Hatchet exclusively owns Job scheduling, retry, worker dispatch, concurrency, durable wait and workflow state. XState remains limited to Device, Account and Network lifecycle. Fleet PostgreSQL repositories remain the deterministic Registry and Lease truth. No second Job state machine exists.

## Adapter feasibility

Thin workflow definitions consume Fleet `ExecutionContext` and emit Fleet-shaped evidence metadata. Hatchet private types remain in `workflows/hatchet`; domain/contracts do not import them.

## Reasons for adoption/rejection

Adopted because the official engine directly satisfies A4 without copying a scheduler, queue or workflow engine. A custom orchestrator and Temporal fallback were not introduced because Hatchet passed the required feasibility and recovery checks.

## Validation evidence

The WSL integration verifies retry, input-derived per-device concurrency, cross-device parallelism, worker labels, four worker slots, durable `NEEDS_HUMAN` event wait, event resume and recovery after replacing the worker while the engine remains running.
