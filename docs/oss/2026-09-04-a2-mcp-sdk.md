# OSS Evaluation: A2 MCP SDK and TypeScript execution tool

- Status: Adopted for A2
- Date: 2026-09-04
- Related ADR: `docs/adr/0004-framework-responsibility-boundaries.md`

## Candidate

Model Context Protocol TypeScript SDK 1.30.0 and tsx 4.23.13.

The locked transitive `esbuild` 0.28.2 install script is explicitly allowlisted because tsx/Vitest require its platform binary; no other dependency build scripts are approved.

## Official repository

- https://github.com/modelcontextprotocol/typescript-sdk
- https://github.com/privatenumber/tsx

## License

Both packages are MIT licensed.

## Activity

Both have current registry releases and active upstream repositories as checked on 2026-09-04.

## API / SDK

The MCP SDK supplies the protocol server and stdio transport. tsx executes TypeScript CLI entry points during development without creating a custom loader.

## Self-host requirement

None. The A2 MCP server uses local stdio.

## Platform requirements

Windows Native Node 24/pnpm 11. Both are portable to Linux and macOS.

## Overlap

The SDK owns MCP protocol framing and transport, not Fleet domain behavior. tsx is development tooling only.

## Adapter feasibility

Fleet tools call the application service through a thin translation layer. MCP types do not enter domain/contracts.

## Reasons for adoption/rejection

Adopted to avoid implementing MCP framing or a TypeScript runtime loader. The Fleet contract remains explicitly `v0.1-draft`.

## Validation evidence

A2 MCP in-memory transport smoke test and fleetctl mock vertical slice.
